# PSP dot_q4 benchmark

## 计算与数据

使用本地 Qwen3-0.6B Q4_0 模型的第一层 `attn_q` 和 `ffn_down`。权重在启动时完整读取到内存，文件读取排除在计算计时之外。准备工具通过 GGUF 库读取模型，通过现有 FHQ4 导出文件及其 JSON 元数据提取与 LLMPSP 相同的 Q4_0 字节。Attention 保留 GGUF 原始 Q4_0 字节；FFN down 使用 LLMPSP 的现有量化器将源文件中的 Q4_1 转为 Q4_0。输入取自真实文本经过第一层计算产生的 attention 输入和 FFN down 输入。每个 Q4_0 block 包含 32 个权重，使用 2 字节 FP16 scale 和 16 字节打包整数。

五个入口使用同一个 `BenchTask`，一次接收完整矩阵任务并写出 `Y[B,N]`。普通 C 在入口内部执行标量点积；LLMPSP 在入口内部准备 block sums，再调用原项目 VFPU 点积；VH2F / VFPU 保留相同流程，将 scale 转换改为 `lhu`、`mtv`、`vh2f.s`。CUSTOM / VMMUL 和 VH2F / VMMUL 使用四行权重、四个输入的 `vmmul.q` 小块。五个实现可以自行安排矩阵遍历，全部数据准备计入运算时间。

共有 21 个项目，默认 QUICK 集合包含八个小规模真实矩阵切片和五个 DOT；FULL 集合增加八个较大矩阵项目。切片支持指定行列起点，列范围按 32 个元素的 Q4 block 选择，保留来源行跨度。完整 attention 投影为 N=2048、K=1024；完整 FFN down 为 N=1024、K=3072。PSP 运行范围是这两个线性投影组件。

两种 VMMUL 由 `src/custom_vfpu.c` 使用编译参数 `BENCH_CUSTOM_VH2F=0/1` 生成，运行时分别调用独立函数。两者共用矩阵遍历、Q4 转换、缩放、乘法和输出代码。CUSTOM / VMMUL 按照原始 dot_q4 的整数算法构造四个 FP32 scale 位模式，再使用 `mtv`；VH2F / VMMUL 使用 `vh2f.p` 转换四个 FP16 scale。两种 VFPU 点积也共用矩阵遍历与 block sums 准备流程，原项目源码直接编译为独立目标文件。

custom 的量化整数转换、缩放与矩阵计算在同一段汇编中完成。CPU 整数指令分离 Q4 高低四位，位模式通过 `mtv` 送入 VFPU；`vc2i.s`、`vi2f.q` 转换量化整数，`vsub.q`、`vscl.q` 恢复浮点权重。输入直接从原始 FP32 矩阵读取。沿 K 方向每次处理 32 个元素，执行八次 4×4 矩阵乘法，16 个累计值跨完整 K 保留在寄存器中。

最终输出小块使用一个 64 字节临时数组。边界分量重复有效行或输入的指针，实际输出数量由真实切片控制。数据文件约 3.52 MiB，程序保留 10 MiB heap 配置与 PSP-1000 的普通内存模式。

## 计时与正确性

每次比较开始前检查全部输出，参考值来自 Python GGUF 解量化后的 FP64 点积。通过正确性检查的实现才能开始计时。报告最大绝对误差和归一化误差；误差阈值根据每个输出的绝对乘积和设置，兼顾接近零的结果。

所有项目均计时完整矩阵入口，包含各实现所需的输入准备、Q4 解码、计算与输出写入。两种 VFPU 点积每次重新计算所需的 block sums。查表初始化、一次性文件读取、正确性检查、界面绘制和 CSV 写入排除在测量窗口之外。每个样本使用连续运行的批次，批次之间处理取消操作并更新界面；累计批次内部的计算时间。

提供固定执行次数和目标计算时间两种停止条件，以及可调的样本数量。记录每个样本的运行次数和累计计算时间；界面显示每次计算微秒的中位数和相对普通 C 的倍数，CSV 额外保存最短值、最长值和有效 GFLOP/s。多个样本循环改变实现顺序，五个样本可以完整轮换五种起始顺序。结果保留实际设置和 CPU/总线频率。用户可以在 PSP 上选择 222、266、333 MHz。

## 界面与输出

原生 480×272 界面使用深蓝渐变、曲线、细线和高亮选择条。L/R 切换测试、设置、结果页面；方向键操作项目，交叉按钮开始比较，START 执行所选 QUICK/FULL 集合，圆圈按钮取消，三角按钮导出 CSV，方块按钮保存截图，SELECT 退出。结果页同时显示五个完整矩阵入口的耗时柱状图。测试页显示真实切片起点。程序控制台使用英文以适应 PSPSDK 字体，操作文档使用中文。

输出同时包含 ISO 和 Memory Stick 的 `EBOOT.PBP` 目录。ISO 包含计算数据与许可证；运行结果写入 `ms0:/PSP/SAVEDATA/DOTQ4BENCH/`。程序按 PSP-1000 的可用内存设计，启动后显示实际剩余内存。

## 构建与验证

在 `psp-dot-q4-bench/` 目录运行 `bash build.sh`。构建使用固定版本的 PSPDEV Docker 镜像，容器内禁用网络。PSPSDK 生成 ELF、PRX、PBP 和 PARAM.SFO，pycdlib 生成 ISO9660 镜像。中间文件保存在 Git 忽略的目录中。

必要测试覆盖真实权重与参考计算、普通 C 编译产物、PSP 上的内核正确性与计时流程、控制器交互与界面、最终 ISO 启动。使用 PPSSPP 的 PSP-1000 配置执行自动测试并保存实际画面。模拟器结果用于验证运行；真机效率需要由 PSP 上的计时结果判断。
