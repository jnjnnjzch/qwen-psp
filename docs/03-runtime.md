# 权重、算子和内存

在 `linear_forward()` 中，Linear 的输入和输出都是向量。
以 MLP 的 `gate_proj` 为例，输入有 1024 个数，权重矩阵有 3072 行、每行 1024 个权重，
输出包含 3072 个数。每一行权重与输入做点积，得到输出中的一个元素。

## 组件与算子的边界

| 位置 | 负责的事情 |
| --- | --- |
| `src/model/qwen3.c` | 决定整个模型如何组合 |
| `src/layers/` | 决定每个组件如何调用投影、归一化、激活和注意力运算 |
| `src/ops/q4.c` | 量化权重的解码与点积 |
| `src/ops/q4_vfpu.c` | PSP 上执行点积的 VFPU 指令实现 |
| `src/ops/attention_vfpu.c` | PSP 上完整 128 维 QK 点积与 V 加权求和的 VFPU 实现 |
| `src/ops/math.c` | RMSNorm、SiLU、Softmax、RoPE 和残差相加 |
| `src/ops/kv_cache.c` | K/V 的 int8 存储与读取，注意力分数与加权求和 |
| `src/storage/` | 保存权重在哪里、哪些部分已缓存、如何读取文件 |

PSP 构建链接 VFPU 点积，电脑构建使用标量点积。两条路径通过 `q4_dot()` 接口调用。

Attention 的公共入口是 `attention_scores()` 和 `attention_weighted_sum()`。
PSP 版本分别调用 `attention_scores_vfpu_128()` 与 `attention_accum_vfpu_128()`；
每次调用处理一个完整的 128 维头。算子内部每轮保留 64 维数据，执行两轮，
QK 将两轮的点积相加，AV 将两轮的结果写入输出向量的对应位置。
每个头的 K/V scale 根据完整的 128 维向量确定，两轮共用同一个头的 scale。

阅读汇编里的地址增量时，可以使用下面的对应关系：

| 一轮处理的数据 | 元素数量 | 字节数量 |
| --- | ---: | ---: |
| Q 的 FP32 元素 | 64 | 256 |
| K 或 V 的 int8 元素 | 64 | 64 |
| AV 的 FP32 输出元素 | 64 | 256 |

QK 在 VFPU 内完成两轮分数的合并。AV 的调用者临时保存每个历史位置的加权系数；
128 个位置需要 512 字节，函数结束后释放这部分临时空间。
`tests/psp_autotest.c` 使用真实推理留下的 Q/K/V，检查完整 128 维计算与标量计算的误差。
每次完成最后一个 DecoderLayer 时，测试程序比较全部 16 个 Q 头，
允许的绝对差值为 `2e-5 * (1 + abs(标量结果))`，并记录实际最大差值。

## 两种位置

`Linear.weight_offset` 是模型文件里的字节位置，`weights_read_file()` 用它定位文件。
`RMSNorm.weight` 是指向内存中数组的 C 指针，计算时通过 `weight[index]` 读取元素。

加载器在 `model_loader.c` 中为各个组件填写这些信息，并读取较小的归一化参数。
矩阵参数的排列方式沿用已经转换好的 FHQ4 v2 文件。

## 一次读取多少行

`basic.c` 中的 `row_batch` 表示一次从文件读取多少行矩阵参数。
读取缓冲区有 32 KiB；如果一行有 576 字节，一次可以容纳 56 行。
这些行依次参与点积，然后缓冲区可以用于下一批读取。

tokenizer 中的 `segment` 表示一段连续文本。它与这里的权重读取批次分别属于不同模块。

## 为什么模型文件大于内存仍然可以计算

当前模型文件为 338307328 字节。程序保存一部分权重缓存，其余权重随计算从文件读取。
`weights.c` 管理这些缓存块，`basic.c` 按当前 Linear 的行顺序读取参数。

`memory.c` 为推理创建中间数组：1024 维主干、2048 维 Q 与注意力拼接结果、
3072 维 MLP 中间结果、151936 维输出分数，以及每一层的 KV 缓存。

128 个位置的 K/V 整数数组合计 7 MiB；每个头的 scale 使用额外的 FP32 数组。
权重缓存使用 6 MiB。其他数组、词表和归一化参数也计入常驻运行数据。
可执行程序、线程和临时分词空间也需要用户内存。

## 继续会话时的 pending_token

生成循环选择一个 token 后，会先将它交给输出回调。当达到回答长度上限时，
这个 token 已经显示，但还没有经过下一次 forward。代码将它保存为 `pending_token`。
继续会话时将它放在新输入的最前面，模型状态就能包含此前显示的全部内容。

`tests/multiturn.c` 用同一段真实对话，比较继续会话和完整重放的输出。
